# CHEBU

Интернет-магазин одежды: сайт **chebustore.ru**, Telegram-бот с Mini App, веб-админка и приложение-админка для iPhone. Всё работает от одного сервера.

```
chebustore/
├── server/            API: Node.js 22, Fastify, Prisma, PostgreSQL, Telegram-бот (grammY)
├── web/               Сайт + Telegram Mini App + веб-админка (React, Vite)
├── ios/               Админка для iPhone (SwiftUI, iOS 17+), только для сотрудников
├── deploy/            Caddy (HTTPS, заголовки безопасности) и сборка сайта
├── docker-compose.yml Запуск всего на сервере одной командой
├── .env.example       Шаблон серверных секретов
└── docs/
    ├── INSTALL.md     Полная установка, обновление, бэкапы, iOS
    └── TELEGRAM.md    Настройка бота, Mini App, входа через Telegram
```

## Что умеет

**Покупатель**
- Каталог с категориями, поиском и сортировкой, карточка товара с фото и размерами.
- Корзина и оформление заказа: СДЭК, Почта России или лично в руки. Подсказки адреса и «Определить мой адрес» (DaData).
- Оплата переводом: покупатель видит реквизиты СБП/карты с логотипом банка внутри своего заказа, переводит и прикрепляет чек (фото или PDF).
- Статусы заказа с уведомлениями в Telegram и на почту:
  `Ожидает оплаты → Проверяем оплату → Собирается → В доставке → Можно забрать → Получен` (или `Отменён`).
- Вход:
  - **сайт** — через Telegram (подтверждение кнопкой в боте, работает без telegram.org) или по коду на почту;
  - **Mini App** — автоматически через Telegram (только Telegram);
- Профиль: привязка второго способа входа, список устройств, «выйти на всех устройствах».
- Всё обновляется в реальном времени без перезагрузки: товары, цены и остатки, цвета и настройки магазина, статусы заказов, корзина в соседних вкладках, а в админке новые заказы и чеки.

**Команда магазина** (роли `Менеджер` и `Администратор`)
- Приложение для iPhone — это только админка: войти в него могут лишь менеджеры и администраторы, покупателю сервер откажет. Вход через Telegram или по коду на почту.
- Проверка чеков в админке (сайт/iPhone) или прямо в Telegram кнопками «Оплата получена / Отклонить».
- Смена статусов, трек-номер, где и когда забрать, внутренние заметки.
- Товары: фото, варианты размер/цвет, остатки, цены и скидки, скрытие.
- Пуш-уведомления на iPhone: новый заказ, чек на проверку, отмена. Нажатие открывает заказ.
- Категории, настройки магазина и доставки, цвета кнопок и фона сайта и приложения, приветственное сообщение бота.
- Только администратор: реквизиты оплаты (банк выбирается из списка банков России), роли и блокировка пользователей, журнал действий.

## Безопасность — коротко

- **Все секреты только на сервере** в файле `.env`: токен бота, SMTP, ключ подписи, пароль базы, ключ DaData, ключ Apple для пушей. В сайте, Mini App и iOS-приложении нет ни одного ключа. Реквизиты оплаты отдаются только владельцу неоплаченного заказа и сотрудникам.
- Сессии — случайные токены; в базе хранится только их HMAC. На сайте токен лежит в `httpOnly`, `Secure`, `SameSite` cookie (недоступна JavaScript). В Mini App токен живёт только в памяти, в iOS — в Keychain («только на этом устройстве»).
- Вход через Telegram: сайт и iPhone получают одноразовую ссылку на бота и секрет, известный только этому устройству. Пользователь подтверждает вход кнопкой в боте, сессия выдаётся один раз и только по секрету. В Mini App сервер проверяет подпись `initData`.
- Код на почту: 6 цифр, 10 минут, 5 попыток, лимиты на отправку. По ответу нельзя узнать, есть ли такой аккаунт.
- Защита от CSRF (проверка Origin + обязательный заголовок), ограничение частоты запросов, строгие CORS/CSP/HSTS.
- Проверка прав на каждом запросе: покупатель видит только свои заказы и чеки. Смена роли или блокировка мгновенно завершает все сессии пользователя.
- Чеки хранятся приватно и отдаются только владельцу и сотрудникам. Изображения перекодируются: метаданные и геолокация удаляются, подделанные файлы отсекаются.
- Контейнеры: база в изолированной сети без доступа снаружи, API — read-only файловая система, без привилегий.
- Журнал действий сотрудников: подтверждения оплат, смена реквизитов, ролей, статусов.
- Живые обновления идут по потоку `/api/events`, в котором нет данных, только сигналы «что изменилось». Сами данные браузер перезапрашивает обычными запросами с проверкой прав. Сигналы о заказе получают только его владелец и сотрудники. Поток закрывается сразу при выходе, завершении сеанса или блокировке.

## Быстрый старт

1. Сервер с Docker, домен `chebustore.ru` указывает на сервер.
2. `cp .env.example .env` и заполнить.
3. `docker compose up -d --build`.
4. Настроить бота в @BotFather.

Подробно по шагам: **[docs/INSTALL.md](docs/INSTALL.md)** и **[docs/TELEGRAM.md](docs/TELEGRAM.md)**.
