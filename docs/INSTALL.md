## 1. Что понадобится

- VPS с Ubuntu 22.04/24.04: минимум 1 vCPU, 2 ГБ RAM, 20 ГБ диска. Подойдут Timeweb, Selectel, REG.RU, Yandex Cloud и т. п. Для соответствия 152-ФЗ лучше выбирать сервер в РФ.
- Домен **chebustore.ru** с доступом к управлению DNS.
- Telegram-аккаунт владельца (для создания бота).
- Почтовый ящик на домене для отправки кодов, например `no-reply@chebustore.ru` в Яндекс 360 или Mail.ru для бизнеса.
- Для iPhone-приложения: Mac с Xcode 16+ и аккаунт Apple Developer (99 $/год), чтобы раздавать приложение сотрудникам через TestFlight.

## 2. Сервер

Подключитесь к серверу по SSH и выполните:

```bash
# обновления
sudo apt update && sudo apt -y upgrade

# отдельный пользователь вместо root
sudo adduser chebu
sudo usermod -aG sudo chebu

# Docker и Compose
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker chebu

# файрвол: только SSH и веб
sudo apt -y install ufw
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 443/udp
sudo ufw enable

# автоматические обновления безопасности
sudo apt -y install unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades
```

Перезайдите на сервер под пользователем `chebu`.

**Рекомендуется:** вход по SSH-ключу вместо пароля. Скопируйте ключ командой `ssh-copy-id chebu@IP` со своего компьютера. Затем на сервере в `/etc/ssh/sshd_config` поставьте `PasswordAuthentication no` и `PermitRootLogin no` и выполните `sudo systemctl restart ssh`.

Скачайте проект:

```bash
git clone https://github.com/<ваш-аккаунт>/chebustore.git
cd chebustore
```

Если репозиторий приватный, создайте на GitHub *Deploy key* (Settings → Deploy keys) или используйте персональный токен.

## 3. Домен и DNS

В панели регистратора домена создайте записи:

| Тип | Имя | Значение |
|-----|-----|----------|
| A | `@` | IP сервера |
| A | `www` | IP сервера |
| AAAA | `@`, `www` | IPv6 сервера (только если он есть) |

Подождите, пока записи обновятся (обычно 5–30 минут). Проверить можно так: `ping chebustore.ru` должен показать IP вашего сервера.

HTTPS-сертификат Let's Encrypt Caddy получит и будет продлевать сам. Для этого порты 80 и 443 должны быть открыты.

## 4. Секреты: файл .env

Все секреты хранятся **только** в файле `.env` на сервере. Он не попадает в git, в сайт или в приложения.

```bash
cp .env.example .env
chmod 600 .env
nano .env
```

Заполните значения. Случайные секреты генерируйте прямо на сервере:

```bash
openssl rand -hex 24      # → POSTGRES_PASSWORD (только hex: символы + / = ломают адрес базы)
openssl rand -hex 48      # → SERVER_SECRET
openssl rand -hex 32      # → TELEGRAM_WEBHOOK_SECRET
```

| Переменная | Что это |
|------------|---------|
| `DOMAIN` | `chebustore.ru` |
| `PUBLIC_URL` | `https://chebustore.ru` (без `/` в конце) |
| `ACME_EMAIL` | Почта для уведомлений Let's Encrypt |
| `POSTGRES_PASSWORD` | Пароль базы. База не видна из интернета, но пароль должен быть длинным. Меняйте его только вместе с паролем внутри базы (раздел 14, «Смена пароля базы») |
| `SERVER_SECRET` | Главный ключ: им хэшируются токены сессий и коды. **Если его сменить, все пользователи разлогинятся** |
| `TELEGRAM_BOT_TOKEN` | Токен от @BotFather (см. [TELEGRAM.md](TELEGRAM.md)) |
| `TELEGRAM_BOT_USERNAME` | Имя бота без `@`, например `chebustore_bot` |
| `TELEGRAM_USE_WEBHOOK` | `true` на сервере |
| `TELEGRAM_WEBHOOK_SECRET` | Случайная строка. По ней сервер понимает, что запрос пришёл от Telegram |
| `TELEGRAM_ADMIN_CHAT_ID` | Необязательно: ID группы, куда приходят чеки на проверку |
| `SMTP_*`, `MAIL_FROM` | Почта для кодов входа (раздел 5) |
| `DADATA_API_KEY` | Необязательно: подсказки адреса при оформлении заказа. Ключ бесплатно выдают на [dadata.ru](https://dadata.ru) → Личный кабинет → «API-ключ» (10 000 подсказок в день). Без ключа покупатель вводит адрес вручную |
| `BOOTSTRAP_ADMIN_EMAILS` | Ваша почта: при первом входе она сразу получит роль администратора |
| `BOOTSTRAP_ADMIN_TELEGRAM_IDS` | Ваш числовой Telegram ID: то же для входа через Telegram |

> Не пересылайте `.env` в мессенджерах и не делайте его скриншоты. Если секрет утёк, замените его и перезапустите сервис: `docker compose up -d`.

## 5. Почта для кодов входа

Без SMTP вход по почте не работает. Вход через Telegram работает и без почты.

**Яндекс 360** (пример):
1. Подключите домен в Яндекс 360 и создайте ящик `no-reply@chebustore.ru`.
2. Войдите в этот ящик → Управление аккаунтом → Безопасность → **Пароли приложений** → создайте пароль для «Почта».
3. В `.env`:
   ```
   SMTP_HOST=smtp.yandex.ru
   SMTP_PORT=465
   SMTP_SECURE=true
   SMTP_USER=no-reply@chebustore.ru
   SMTP_PASS=<пароль приложения>
   MAIL_FROM=CHEBU <no-reply@chebustore.ru>
   ```

Чтобы письма не попадали в спам, добавьте в DNS записи, которые покажет Яндекс 360: **SPF** (TXT `v=spf1 redirect=_spf.yandex.net`), **DKIM** (TXT `mail._domainkey`) и **DMARC** (TXT `_dmarc` → `v=DMARC1; p=none`).

Mail.ru для бизнеса: `smtp.mail.ru`, порт `465`, тоже с паролем приложения.

## 6. Запуск

```bash
docker compose up -d --build
```

Первая сборка занимает 3–7 минут. При запуске автоматически:
- применяются миграции базы;
- создаются стартовые категории и настройки магазина;
- Caddy получает HTTPS-сертификат;
- бот регистрирует webhook, команды и кнопку меню.

Проверка:

```bash
docker compose ps                        # все три сервиса в состоянии running / healthy
curl https://chebustore.ru/api/health    # {"ok":true}
docker compose logs -f api               # логи API; должна быть строка «telegram: webhook mode»
```

Откройте https://chebustore.ru — должен появиться каталог.

## 7. Первый вход и назначение администратора

**Вариант А: автоматически.** Если в `.env` указаны `BOOTSTRAP_ADMIN_EMAILS` или `BOOTSTRAP_ADMIN_TELEGRAM_IDS`, войдите на сайте этой почтой или этим Telegram — роль администратора назначится сама.

**Вариант Б: командой на сервере:**

```bash
docker compose exec api node dist/scripts/makeAdmin.js admin@chebustore.ru ADMIN
# или по Telegram ID:
docker compose exec api node dist/scripts/makeAdmin.js 123456789 ADMIN
# назначить менеджера:
docker compose exec api node dist/scripts/makeAdmin.js manager@mail.ru MANAGER
```

После смены роли войдите заново. Все старые сессии этого пользователя завершаются.

Дальше роли удобнее менять в админке: **Админка → Пользователи**.

| Роль | Что может |
|------|-----------|
| Покупатель | Покупки, свои заказы |
| Менеджер | Заказы, проверка чеков, статусы, товары, категории |
| Администратор | Всё то же + реквизиты оплаты, настройки магазина, роли, блокировки, журнал |

> Чтобы получать чеки в Telegram и подтверждать их кнопками, сотрудник должен **привязать Telegram** в профиле на сайте (Профиль → Telegram → Привязать), если входил по почте.

## 8. Первичная настройка магазина

Сайт → **Профиль → Админка** или приложение CHEBU для iPhone:

1. **Настройки → Реквизиты**: телефон СБП и банк (выбирается из списка с логотипами), номер карты и банк, получатель, срок оплаты (по умолчанию 24 часа), инструкция покупателю. Пока реквизиты не заполнены, оформить заказ нельзя.
2. **Настройки → Магазин**: название, Telegram и почта поддержки.
3. **Настройки → Доставка**: СДЭК, Почта России и «Лично в руки» — цена и переключатель для каждого способа, плюс где и когда вы передаёте заказ лично.
4. **Настройки → Оформление**: цвет кнопок и акцентов (готовые наборы или свой цвет для светлой и тёмной темы). Меняется сразу на сайте, в Mini App и в приложении для iPhone.
5. **Настройки → Приветствие бота**: текст, который бот отправляет на `/start`, и надпись на кнопке. Ниже видно, как это будет выглядеть в Telegram.
6. **Категории**: переименуйте стартовые или создайте свои.
7. **Товары → Новый товар**: название, категория, цена, описание → Сохранить → добавьте фото (первое станет обложкой) и размеры с остатками → Сохранить. Товар без вариантов в наличии купить нельзя.

## 9. Как проходит заказ

1. Покупатель оформляет заказ. Товар резервируется на складе, покупатель видит реквизиты и сумму.
2. Он переводит деньги и прикрепляет чек. Заказ переходит в статус **«Проверяем оплату»**.
3. Сотрудникам приходит фото чека в Telegram с кнопками. Этот же заказ появляется в админке с пометкой «Чеков на проверке».
4. Сверьте поступление в банке и нажмите:
   - **«Оплата получена»** → заказ переходит в статус **«Собирается»**;
   - **«Отклонить»** с причиной → покупатель видит причину и может прикрепить новый чек, срок оплаты продлевается.
5. Дальше меняйте статусы: **В доставке** (можно указать трек-номер) → **Можно забрать** (где и когда) → **Получен**.
6. О каждом статусе покупатель получает сообщение в Telegram и/или письмо.

Неоплаченные заказы отменяются автоматически по истечении срока, товар возвращается на склад. При ручной отмене остатки тоже возвращаются.

## 11. Резервные копии

Что нужно сохранять:
- базу данных (volume `pgdata`);
- файлы: фото товаров и чеки (volume `appdata`);
- `.env` — храните его отдельно, в менеджере паролей.

Скрипт `~/backup.sh`:

```bash
#!/bin/sh
set -e
cd ~/chebustore
D=~/backups/$(date +%F)
mkdir -p "$D"
docker compose exec -T db pg_dump -U chebu -Fc chebustore > "$D/db.dump"
docker run --rm -v chebustore_appdata:/data -v "$D":/out alpine tar czf /out/files.tgz -C /data .
find ~/backups -maxdepth 1 -type d -mtime +14 -exec rm -rf {} +
```

```bash
chmod +x ~/backup.sh
crontab -e
# каждый день в 04:00:
0 4 * * * /home/chebu/backup.sh >> /home/chebu/backup.log 2>&1
```

Бэкапы копируйте за пределы сервера, например в S3-хранилище Selectel или Yandex Object Storage через `rclone`. В архиве есть чеки покупателей, храните его как персональные данные.

**Восстановление:**

```bash
docker compose up -d db
docker compose exec -T db pg_restore -U chebu -d chebustore --clean --if-exists < ~/backups/2026-09-26/db.dump
docker run --rm -v chebustore_appdata:/data -v ~/backups/2026-09-26:/in alpine sh -c "cd /data && tar xzf /in/files.tgz"
docker compose up -d
```

## 12. Приложение для iPhone (админка)

Проект: `ios/ChebuStore.xcodeproj`. Это приложение только для сотрудников: сводка и выручка, заказы и проверка чеков, смена статусов, товары с фото и остатками, настройки и реквизиты, пользователи и роли. Войти могут только менеджеры и администраторы: сервер отказывает во входе и в запросах от приложения всем остальным. Приложение обращается к `https://chebustore.ru`, поэтому сервер должен быть уже запущен.

**Запуск на своём iPhone:**
1. Откройте `ios/ChebuStore.xcodeproj` в Xcode 16+.
2. Выберите таргет **ChebuStore** → **Signing & Capabilities** → **Team** — ваш аккаунт разработчика. Если Bundle ID `ru.chebustore.app` занят, замените его на свой.
3. Подключите iPhone кабелем и выберите его вверху окна Xcode.
4. Нажмите ⌘R. При первом запуске на телефоне откройте Настройки → Основные → VPN и управление устройством и доверьте разработчику.

**Раздача сотрудникам.** Приложение внутреннее, публиковать его в открытом App Store не нужно. Удобнее всего TestFlight: Product → Archive → Distribute App → App Store Connect → TestFlight, затем добавьте сотрудников во внутреннее тестирование по их Apple ID. Сборка TestFlight работает 90 дней, потом загрузите новую. Для постоянной раздачи без TestFlight подойдёт Custom App через Apple Business Manager.

**Как работает вход через Telegram в приложении.** Приложение открывает Telegram с чатом бота, бот спрашивает «Подтвердить вход?». После нажатия вернитесь в приложение — вход завершится сам. Войти так может только менеджер или администратор. Токен бота в приложение не попадает.

## 13. Локальная разработка

Нужны Node.js 22+ и Docker (для Postgres).

```bash
# база
docker run -d --name chebu-pg -e POSTGRES_PASSWORD=dev -e POSTGRES_DB=chebustore -p 5432:5432 postgres:16-alpine

# сервер
cd server
npm install
cat > .env <<'EOF'
NODE_ENV=development
PUBLIC_URL=http://localhost:5173
DATABASE_URL=postgresql://postgres:dev@localhost:5432/chebustore
SERVER_SECRET=dev-secret-dev-secret-dev-secret-dev-secret
TELEGRAM_BOT_TOKEN=<токен ОТДЕЛЬНОГО тестового бота>
TELEGRAM_BOT_USERNAME=<имя тестового бота>
TELEGRAM_USE_WEBHOOK=false
BOOTSTRAP_ADMIN_EMAILS=you@example.com
EOF
npx prisma migrate deploy
npx tsx --env-file=.env src/scripts/seed.ts
npm run dev          # API на http://localhost:4000

# сайт (в другом терминале)
cd web
npm install
npm run dev          # http://localhost:5173
```

- Без SMTP код входа печатается в консоли сервера: `[mail:dev] ... Код для входа: 123456`.
- Бот локально работает в режиме polling. Используйте **отдельного тестового бота**: если запустить боевого бота в polling, у него снимется webhook.
- Вход через Telegram локально работает с тестовым ботом: бот в режиме polling получает `/start` и присылает кнопку подтверждения.
- Тесты: `cd server && npm test`.

## 14. Решение проблем

| Симптом | Что проверить |
|---------|---------------|
| Сайт не открывается, ошибка сертификата | DNS указывает на сервер? Порты 80/443 открыты? `docker compose logs web` |
| `api` постоянно перезапускается | `docker compose logs api`: обычно в `.env` не заполнена обязательная переменная, об этом будет понятное сообщение |
| `P1000: Authentication failed` в логах api | Пароль в `.env` не совпадает с паролем базы — см. «Смена пароля базы» ниже |
| Сборка зависает на `npm run build` | Мало памяти: добавьте подкачку `fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile` |
| Бот не отвечает | `docker compose logs api \| grep telegram`. Верный ли токен? Проверьте `https://api.telegram.org/bot<ТОКЕН>/getWebhookInfo`: `url` должен быть `https://chebustore.ru/api/telegram/webhook`, `last_error_message` пустой |
| Нажал «Войти через Telegram», бот не прислал подтверждение | Бот должен работать (`/start` отвечает). Смотрите `docker compose logs api \| grep telegram` и раздел «Бот не отвечает» |
| Не приходит код на почту | SMTP-логин и пароль приложения, `docker compose logs api \| grep -i mail`, папка «Спам», записи SPF/DKIM |
| «Слишком много попыток» | Сработала защита от перебора: подождите 10–15 минут |
| Не приходят чеки в Telegram | Сотрудник привязал Telegram в профиле и хотя бы раз нажал /start у бота? Если задан `TELEGRAM_ADMIN_CHAT_ID`, бот добавлен в эту группу? |
| Нельзя оформить заказ | Заполнены реквизиты оплаты (телефон СБП или номер карты)? Включён хотя бы один способ доставки? У товара есть варианты с остатком? |
| Не появляются подсказки адреса | В `.env` задан `DADATA_API_KEY`? После изменения `.env` выполните `docker compose up -d` |
| Мало места на диске | `docker system df`, `docker image prune -a`, проверьте размер бэкапов |

**Смена пароля базы** (данные сохраняются):

```bash
cd ~/chebustore
sed -i "s|^POSTGRES_PASSWORD=.*|POSTGRES_PASSWORD=$(openssl rand -hex 24)|" .env
docker compose exec db psql -U chebu -d chebustore -c "ALTER USER chebu PASSWORD '$(grep ^POSTGRES_PASSWORD= .env | cut -d= -f2)';"
docker compose up -d
```

## 15. Чек-лист безопасности

- [ ] `.env` имеет права `600`, в git его нет (`git status` его не показывает).
- [ ] Все секреты сгенерированы через `openssl rand`, нигде не повторяются и нигде не опубликованы.
- [ ] SSH только по ключу, root-вход отключён, включён `ufw`.
- [ ] Включены автоматические обновления безопасности.
- [ ] Настроен ежедневный бэкап с копией вне сервера, восстановление хотя бы раз проверено.
- [ ] Администраторов — минимум необходимого, остальным сотрудникам дана роль «Менеджер».
- [ ] Реквизиты в настройках проверены. Изменения реквизитов видны в **Журнале** — периодически его просматривайте.
- [ ] Токен бота есть только в `.env`. При подозрении на утечку: @BotFather → `/revoke` → новый токен в `.env` → `docker compose up -d`.
- [ ] На сайте опубликована политика обработки персональных данных (152-ФЗ): собираются имя, телефон, адрес, почта.
